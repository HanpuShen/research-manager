How it works

One memory folder, three ways in: the VS Code app, the research CLI, and an MCP server for agents.

Markdown you own

Each record is a Markdown file with YAML front matter. A local index keeps it fast, and every change keeps the previous version in history/.

Agents with a small context

A project handoff is about 20 KB instead of megabytes. Agents read one claim's evidence at a time, search ranked cards, and check their records with research_lint.

Human-only judgments

Agents propose verdicts and back-burner moves; only you accept them. Nothing is deleted: refuted work keeps its evidence and can be restored.

Get started

About five minutes, with the demo project.

Install the extension

Download research-manager-0.1.9.vsix from Releases, then in VS Code choose Extensions → … → Install from VSIX and run Research Manager: Open.

Get the CLI, MCP server and demo

Agents use the research command from a clone of the repository. On Linux the bootstrap installs Node 24 locally and builds; on macOS or Windows install Node 24, then run npm ci && npm run build.

git clone https://github.com/HanpuShen/research-manager.git
cd research-manager && ./scripts/bootstrap.sh

To see the demo, run Research Manager: Set Memory Folder and choose examples/demo-memory in the clone.

Connect your agent

Any MCP client works. With Claude Code, from the clone:

claude mcp add research-manager -- "$PWD/bin/research" \
  --memory /path/to/research-memory mcp

Then ask: “Read the handoff for my project and tell me what needs a decision.” Add --read-only for an agent that should analyse but not write.
